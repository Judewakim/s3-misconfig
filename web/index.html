Find the S3 buckets that would end up in a breach report.

S3 Sentry checks every bucket in an AWS account for public access, missing encryption and settings that make data impossible to recover, and maps each problem to NIST CSF controls.

    How it works

    No code in your account

    You deploy one IAM role. S3 Sentry assumes it from its own account with a per-customer External ID, which blocks the confused-deputy attack, and a trust condition that admits only its two Lambda roles.

    Scheduled, serverless scans

    EventBridge triggers a container Lambda daily. It runs Prowler's S3 checks, maps each failure to NIST CSF, and stores findings in S3 Sentry's own DynamoDB table, never in your account.

    Fixes you approve by email

    The full version emails each finding with Fix and Ignore links signed with HMAC-SHA256. A link works once, expires in 24 hours and stops working after a newer scan. Current settings are saved to a vault before any change. The live demo is read-only, so it skips this step.
