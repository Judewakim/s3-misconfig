S3 Sentry

Finds the S3 buckets that would end up in a breach report: public, unencrypted, or impossible to recover. Then fixes them with one click, after taking a snapshot so every fix can be rolled back.

    How it works

    No code in your account

    Customers deploy one IAM role. S3 Sentry assumes it from its own account using a per-customer External ID, which blocks the confused-deputy attack, and a trust condition that admits only its two Lambda roles.

    Scheduled, serverless scans

    EventBridge triggers a containerized Lambda daily. It runs Prowler's S3 checks, maps every failure to NIST CSF controls, and stores the findings in S3 Sentry's own DynamoDB table, never in the customer's account.

    Fixes you approve by email

    Paying customers get a scan email where each finding has Fix and Ignore links signed with HMAC-SHA256. The live demo skips this because its role is read-only; the sample scan shows what a fix changes. A link works once, expires in 24 hours and dies when a newer scan runs. The current configuration is saved to a vault before any change, so it can be rolled back.

    Built with Python, AWS Lambda (container image), EventBridge, DynamoDB, STS, SES, SSM Parameter Store, CloudFormation and Prowler.
